# 双色球数据分析与号码推荐系统 —— 成熟路线方案

> 定位：**概率推荐与回测系统**，不是“必中预测器”。
> 双色球开奖接近独立随机过程，任何模型都很难长期显著优于随机；系统价值在于数据透明、可解释推荐与严格回测。

公平开奖下，任一合法单注中一等奖的概率相同：

$$
P=\frac{1}{\binom{33}{6}\times 16}=\frac{1}{17\,721\,088}
$$

## 核心认知（设计前提）
1. 公平开奖下所有合法组合中奖概率相同，**任何策略都无法提高单注中奖概率**，除非开奖存在可检测的偏差。
2. 因此系统真正可做、且有依据的只有三件事：
   - **检验偏差**：用统计检验判断历史数据是否偏离随机（大概率不偏离）。
   - **降低分奖**：一、二等奖为浮动奖金、同注均分，避开大众偏好的号码可提高“中奖时”的期望奖金——这是唯一有理论依据的优化方向。
   - **透明可核验**：推荐开奖前固化、开奖后自动对账，与随机基线公开对比。
3. 冷热、遗漏、结构筛选等传统选号法作为“待检验假设”纳入回测，不预设有效。

---

## 总体架构

```
数据采集层 → 数据存储层 → 数据分析层 → 算法层 → 回测评估层 → 接口层 → 小程序产品层
                                                                    ↑
                                                         合规与风控（贯穿全程）
```

## 1. 数据采集层

### 1.1 数据源
| 优先级 | 来源 | 说明 |
|---|---|---|
| 主 | 中国福彩网官方查询接口 | `https://www.cwl.gov.cn/cwl_admin/front/cwlkj/search/kjxx/findDrawNotice` |
| 备 | 第三方开奖接口 / 本地历史缓存 | 主源失败时兜底，仅用于补漏与交叉校验 |

### 1.2 主接口参数
| 参数 | 含义 | 示例 |
|---|---|---|
| `name` | 彩种 | `ssq` |
| `issueCount` | 最近 N 期 | `100` |
| `issueStart` / `issueEnd` | 期号区间 | `2026001` / `2026124` |
| `dayStart` / `dayEnd` | 日期区间 | `2026-01-01` / `2026-10-31` |
| `pageNo` / `pageSize` | 分页 | `1` / `30` |
| `systemType` | 终端类型 | `PC` |

### 1.3 返回结构
- 顶层：`state`(0=成功)、`message`、`total`、`pageNum`(总页数)、`pageNo`、`pageSize`、`result[]`
- `result[i]` 核心字段：
  - `code` 期号、`date` 开奖日期（形如 `2026-10-29(四)`，需截取前 10 位）、`week`
  - `red` 红球（`"03,11,17,22,23,29"`）、`blue` 蓝球（`"09"`）
  - `sales` 销售额、`poolmoney` 奖池、`content` 一等奖地区分布
  - `prizegrades[]`：`type` 奖级、`typenum` 注数、`typemoney` 单注奖金

### 1.4 采集策略
- **服务端采集**，不在小程序前端直连（规避 CORS 与频控）。
- **全量初始化**：按期号/日期区间分页拉取数据。2026-10-31 实测本接口仅覆盖 2013001–2026124，共 2,082 期；2003–2012 年须另源补齐，完成前不得声称已取得双色球全部历史。
- **增量更新**：查询库内最大期号，只拉更新的期；开奖日（周二/四/日）21:15 后定时执行，失败按退避重试。
- 请求设置合理 `User-Agent`、`Referer`，控制频率（间隔 ≥1s），不并发轰炸。
- 原始响应落盘留档，便于字段变更时回放解析。
- 停售期（春节等）不开奖：下期期号/日期按官方开奖日历推算，不能简单按周二/四/日递推。
- 官方发布可能延迟：当晚未取到则次日补拉；`prizegrades` 可能晚于号码公布，需二次更新。

### 1.5 数据校验
- [ ] 红球 6 个、互不重复、范围 1–33；蓝球 1 个、范围 1–16
- [ ] 期号唯一（`issue` 唯一键，upsert 去重）
- [ ] 期号连续性检查（跨年期号重置，按年内连续校验）
- [ ] 日期与期号单调一致
- [ ] 空字符串字段统一转 `null`
- [ ] 主备源交叉比对，不一致时告警而非覆盖
- [ ] 奖级完整性：`prizegrades` 为空的期标记“待补全”，后续重拉

## 2. 数据存储层

### 2.1 `draws` 开奖表
| 字段 | 类型 | 说明 |
|---|---|---|
| `issue` | string, unique | 期号 |
| `draw_date` | date | 开奖日期 |
| `reds` | int[6] | 升序红球 |
| `blue` | int | 蓝球 |
| `sales` | bigint | 销售额 |
| `pool_money` | bigint | 奖池 |
| `prize_grades` | json | 奖级明细 |
| `source` | string | 数据来源 |
| `fetched_at` | datetime | 采集时间 |

### 2.2 其他表
- `recommendations`：每期推荐结果——期号、策略名、**策略版本**、参数、随机种子、号码、评分、生成时间、**内容哈希**；开奖前写入，只读不改
- `backtest_runs`：回测任务、参数、指标汇总（明细存 JSON 文件）
- `fetch_logs`：采集日志（时间、范围、条数、状态、错误）

### 2.3 简化原则
- 全量历史仅约 3,600 期，数据量很小：MVP 用 **SQLite** 即可；统计与特征**按需计算 + 开奖后缓存**，不单独建 `features` 表。
- 推荐记录的内容哈希按期公开（或写入日志），使“开奖前生成”可被第三方验证。

## 3. 数据分析层

### 3.1 单号统计
- 红球/蓝球出现频次（全量、近 30/100/300 期）
- 当前遗漏、历史最大遗漏、平均遗漏、遗漏分布
- 冷热分级（基于滚动窗口频次分位数）

### 3.2 组合特征
- 红球和值、跨度、奇偶比、大小比、三分区比（1–11/12–22/23–33）
- 连号组数、与上期重号数、尾数分布、AC 值
- 蓝球奇偶、大小、振幅

### 3.3 随机性检验
- **零分布用蒙特卡洛模拟**：按真实规则（33 选 6 不放回 + 16 选 1）模拟 ≥10,000 组与历史等长的开奖序列，以模拟分布计算 p 值。红球同期号码负相关，标准卡方分布不再精确，模拟法最稳妥且适用于任意统计量。
- 检验项：单号频次均匀性、遗漏长度分布、组合特征分布（和值/奇偶/连号等）、跨期相关（上期重号数、自相关）
- 分段检验：按年份分段，观察偏差是否稳定存在（不稳定的“偏差”不可利用）
- 多重检验校正（BH 控制 FDR），避免把偶然波动当成规律
- 输出结论：**是否存在可利用偏差**；该结论决定算法层的投入深度（见第 9 节）

### 3.4 号码热度（分奖）分析
利用 `sales` 与 `prizegrades` 估计“开奖组合的大众热度”：
- 每期投注注数 $T=\text{sales}/2$（单注 2 元）
- 均匀投注假设下的期望中奖注数：一等奖 $T/17\,721\,088$，二等奖 $15T/17\,721\,088$，三等奖 $162T/17\,721\,088$
- 热度指数 = 实际中奖注数 / 期望中奖注数；三等奖样本量更大，估计更稳定
- 以热度指数为因变量，回归组合特征：≤31 号码个数（生日效应）、连号、等差/图形规律、与上期重号、同尾号等
- 机选注近似均匀，会稀释信号但不改变方向
- 产出：各特征对“撞号人数”的影响系数，供算法层 M5 使用

> 注意：红球是 33 选 6 不放回，同期号码不独立，建模时不能当成 33 次独立伯努利试验。

## 4. 算法层（推荐而非预测）

### 4.1 模型清单
| 模型 | 思路 | 作用 |
|---|---|---|
| M0 均匀随机 | 等概率不放回抽样 | **必须保留的对照基线** |
| M1 平滑频次 | 历史频次 + 拉普拉斯/贝叶斯平滑 | 防小样本过拟合 |
| M2 时间衰减 | 指数衰减加权频次，半衰期可调 | 检验近期信息是否有样本外价值 |
| M3 冷热遗漏 | 热号/冷号/遗漏回补权重 | 待验证假设；“遗漏回补”即赌徒谬误，独立开奖下无效，仅作对照 |
| M4 融合打分 | M1–M3 加权融合，权重按回测对数损失确定 | 综合推荐；若各模型均不优于 M0，权重自动退化为均匀 |
| M5 反热门 | 依据 3.4 热度回归，降低大众偏好组合的权重 | **不改变中奖概率，提高中奖时的期望奖金**；可与任一模型叠加 |

### 4.2 组合生成
1. 由模型得到红球权重向量 $w_r\in\mathbb{R}^{33}$、蓝球权重 $w_b\in\mathbb{R}^{16}$
2. 加权**不放回**蒙特卡洛采样生成候选组合
3. 结构约束筛选（和值区间、奇偶比等，可配置）——仅作选号偏好，**不提高中奖概率**；“看起来常见”的结构往往也是大众偏好，可能增加分奖，默认关闭，经 M5 评估后再开启
4. 多注去重与分散：限制注间红球重叠数，提高覆盖面
5. 输出 Top N 注，附评分、所用策略、特征说明

### 4.3 输出约定
- “评分”≠“中奖概率”，界面与接口中不得混用
- 每次推荐记录随机种子、参数与策略版本，结果可复现
- 每注同时展示中奖概率（所有合法单注相同）与 M5 估计的“相对撞号热度”

## 5. 回测评估层

### 5.1 方法
- **滚动回测（walk-forward）**：预测第 $t$ 期只使用 $t-1$ 期及以前的数据
- 数据切分：训练/调参段与最终评估段严格分离，防止数据泄漏
- 随机基线：M0 在**相同注数、相同成本**下重复多次（如 1000 次），得到分布

### 5.2 指标（按统计功效分层）
| 层级 | 指标 | 说明 |
|---|---|---|
| 主指标 | 号码级对数损失 / Brier 分数 | 每期 33 个红球、16 个蓝球视为二元事件，基线概率 $6/33$、$1/16$；每期都有信号，功效最高 |
| 主指标 | 平均红球命中数、蓝球命中率 | 随机期望：红球 $36/33\approx1.091$，蓝球 $1/16=0.0625$ |
| 次指标 | 奖级命中次数、ROI、最大回撤 | 高奖级极稀有、方差极大，**不能作为策略有效的依据** |
| 分奖指标 | 中奖时的估计单注奖金 | 用于评估 M5 |

- 奖金按每期 `prizegrades` 的**实际奖金**计算，兼容历史规则调整与浮动奖金
- 所有指标给出相对随机基线的差异、置信区间和 p 值

### 5.3 统计功效与防过拟合
- **功效估算**：单注红球命中数标准差约 0.87；约 3,600 期、每期 1 注时标准误约 0.015，最小可检测差异约 0.04（相对约 4%）。更小的“优势”在历史数据上无法与噪声区分；增加每期注数帮助有限（同期各注共享同一开奖）。
- **登记搜索次数**：记录尝试过的策略 × 参数组合数量；尝试越多，越需要更严格的校正或更长的保留段
- **保留段只用一次**：最终评估段在定稿前不得查看
- **前瞻验证**：上线后开奖前固化的真实推荐才是最可信的样本外证据，持续累积并公开

### 5.4 验收标准
- 样本外及前瞻验证均显著优于随机基线 → 可展示为“历史回测表现”
- 否则如实输出：**“未发现优于随机的证据”**，产品定位为娱乐型推荐

## 8. 合规与风控

- 显著位置声明：**仅供娱乐与数据研究，不构成购彩建议，不承诺任何收益**
- 禁止使用“精准预测”“必中”“稳赚”等宣传用语
- 不提供代购、不涉及资金交易、不引导加大投注
- **上线可行性前置确认**：微信等平台对彩票类内容审核严格，通常要求企业主体及相应资质，个人主体可能无法过审；P0 阶段先核实类目要求，备选方案为 H5 或自用工具
- 数据来源标注，采集遵守目标站点访问频率，不做高频抓取
- 提示理性购彩、未成年人不得购彩

## 9. 实施里程碑

> 分批执行细节见 [实施计划.md](实施计划.md)。

| 阶段 | 内容 | 交付物 | 状态 |

| P1 | 数据采集 + 存储 + 校验 | 全量历史入库、增量定时任务 | [x] 数据源已确认 / [ ] 实现 |
| P2 | 数据分析层 | 统计指标、蒙特卡洛随机性检验、热度回归 | [ ] |
| P3 | 回测引擎 + M0 基线 | 滚动回测框架、分层指标体系 | [ ] |
| P4 | 算法层 | M1–M5、组合生成器，逐个经回测准入 | [ ] |

| P6 | 前端 | 第 7 节页面 | [ ] |
| P7 | 上线与前瞻验证 | 免责声明、监控告警、推荐固化与自动核验 | [ ] |

### 原则
1. 先简单可解释，后复杂；深度学习等仅在回测证明简单模型有价值后再评估。
2. **回测引擎先于模型**：先有 M0 基线与评估框架，再逐个接入模型。
3. 每个新策略上线前必须通过回测，并与随机基线对比。
4. **按 P2 结论控制投入**：若“无可利用偏差”，P4 只实现 M0、M5 及简单的 M1/M2 作为对照，不再投入复杂模型。
5. 推荐结果开奖前固化存档，开奖后自动核验，全程透明。
