# 实施计划（分批实现）

> 依据：[成熟路线方案.md](成熟路线方案.md)。每批完成后先验证再进入下一批，并在本文件勾选。

## 一、技术选型

| 部分 | 选型 | 说明 |
|---|---|---|
| 后端 | Node.js + TypeScript + Express | 与现有项目一致 |
| 数据库 | SQLite（better-sqlite3） | 全部历史约 3,600 期，数据量小 |
| 定时任务 | 自写简易调度器（按北京时间） | node-cron 3 依赖有漏洞、修复版需 Node 20，需求简单故自行实现 |
| 随机数 | 可设种子的伪随机数生成器 | 推荐与回测结果可复现 |
| 统计计算 | 自行实现（模拟检验、BH 校正、最小二乘回归） | 用到的方法少，不引入大型统计库 |
| 测试 | vitest | 只覆盖号码校验、奖级判定、回测防泄漏三处 |
| 前端 | 原生微信小程序 + TypeScript + TDesign | |
| 图表 | 冷热格、遗漏表、频次条形图用 WXML + WXSS 画；走势和回测曲线用 ECharts 定制版，放分包 | |

## 二、目录结构

```
ssq-predictor/
  docs/            方案、计划、UI 规范、分析报告
  server/
    src/
      config/      配置
      db/          建表与数据访问
      collector/   采集、解析、校验
      calendar/    开奖日历（含停售期）
      analysis/    统计、随机性检验、热度回归
      models/      M0–M5
      generator/   组合生成
      backtest/    回测与指标
      recommend/   推荐固化与开奖核验
      api/         接口路由
      jobs/        定时任务
    scripts/       全量导入、生成报告、运行回测等命令
    data/          数据库文件、原始响应存档、报告输出
  miniprogram/     小程序
```

### 第 4 批：基础统计
- [x] 单号统计：频次（全部可用历史、近 30 / 100 / 300 期）、当前遗漏、观测最大遗漏、完整最大/平均遗漏、完整遗漏分布、冷热分级
- [x] 组合特征：和值、跨度、奇偶比、大小比、三分区比、连号组数/相邻对数、上期重号、尾数、AC 值；蓝球奇偶、大小、振幅；包含走势图序列及特征频数分布
- [x] 结果缓存：数据库隔离、16 项有界缓存、号码快照指纹；新增/删除/修正开奖后下次读取失效重算，结果递归冻结防止缓存污染
- [x] 历史截止支持：`asOfIssue` 包含式截止；窗口首期可读取窗口外紧邻上期，跨缺期重号和振幅返回 null；缺期、样本不足、早期历史未覆盖均提示
- **验收（2026-10-31）**：类型检查与构建通过，原有 21 项测试通过；`npm run verify:basic` 共 27 项通过（手算遗漏与组合、真实频次独立 SQL、缓存失效、截止隔离等）。真实 2026124 和值 105、跨度 26、奇偶 5:1、分区 2:2:2、AC=7，与手算一致。
- **运行**：`npm run analyze:basic` 输出全量/30/100/300 期简报及 JSON；可加 `-- --window=30 --as-of-issue=2026123` 核查历史时点；输出目录为 `server/data/reports/`。
- **口径**：遗漏按未出现的期数计，相邻两期出现遗漏为 0；平均遗漏仅计算两次出现之间完整间隔，窗口两端截断区间不参与均值，未出现过的号码当前遗漏标记为下界；红球大小以 16 为界，蓝球以 8 为界；冷热按同色频次 25%/75% 分位点严格划分，并列值不强行拆分。

### 第 5 批：随机性检验与热度分析（检查点）
- [x] 按真实规则生成模拟开奖序列（10,000 组，与真实序列等长，固定种子可复现）
- [x] 检验：单号频次均匀性、完整遗漏分布、和值/奇偶/连号分布、跨期相关；全量及按年份分段；全部预定义检验统一 BH 校正
- [x] 热度指数：用 `sales` 与 `prizegrades` 计算一至三等奖实际中奖注数与期望注数之比
- [x] 热度回归：生日号、连号、等差三元组、上期重号、同尾号；Poisson offset GLM、训练段标准化及时间留出评估。不推断缺乏投注布局数据的图形偏好。
- [x] 输出正式 JSON 分析报告到 `docs/research-analysis.json`
- **检查点**：和你一起看报告，按“是否存在可利用偏差”确定第 7、8 批做多少
  - **代码已验收，检查点待用户审阅**：类型检查/构建通过；原有 21 项测试、基础 27 项验收、研究 28 项验收全部通过。`npm run analyze:research` 默认 10,000 次、种子 20261031；支持 `-- --simulations=100 --seed=123` 烟测（非正式报告）。正式 JSON 为 `docs/research-analysis.json`，烟测为 `server/data/reports/research-analysis-smoke-重复数-种子.json`；`npm run verify:research` 可重复验收。
  - **统计口径**：全量及每年份固定十项检验统一 BH；公平 33 不放回选 6、16 选 1，Pearson 型量仅作为距离，全部用同长序列 Monte Carlo 校准，不套红球标准卡方临界值；完整遗漏按有限样本端点截断处理，缺期或疑似年末缺期跳过连续检验。
  - **热度口径**：一/二/三等奖分别用销售额/2及概率 1/15/162 除以 17,721,088；带 offset 的 Poisson GLM（ml-matrix SVD）只在训练段标准化，训练截至 2022150，后续评估 2023001–2026124；生日号、连号、同尾、等差三元组、上期重号，不臆测图形。三等奖仅为 5 红+蓝邻域，不是精准六红组合热度。
  - **检查结果（2026-10-31）**：2082 期、2013001–2026124、无范围内序列问题；正式 10,000 次耗时约 12.53 秒，150 项统一 BH 后拒绝 0 项。不证明完全随机，也未建立可利用预测偏差；三个热度模型的保守家族区间均含 0，不准入 M5。第 6 批未实现，福运奖/派奖条件核实前不计算 ROI。
  - **后续建议**：第 6 批优先建立 M0 随机基线与防泄漏回测；M1/M2 仅作简单对照，不因当前结果投入复杂模型；M5 暂保留研究状态。2023 年起评估段已被查看，不得再标为未触碰的最终保留段，最终确认需新预留方案或前瞻数据。
